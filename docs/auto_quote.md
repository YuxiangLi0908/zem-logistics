# 自动询价

三方询价页面选择“自动询价”，选择 LA / SAV / NJ 地址组。展开“上传 Excel / 查看地址”导入或分页检查地址。

Excel 使用 `.xlsx`，首行为表头，A列忽略，B～F列依次为：城市、州、邮编、详细地址、距仓库距离（miles）。每个有效行保存一条地址；空行跳过，数字邮编补足5位，保留 ZIP+4。距离可以为空。任何错误行都会阻止本次整份导入并显示行号；修正后重传。同组相同城市、州、邮编、地址跳过，不重复新增，也不修改已存在记录。不同组可以保留相同地址。

选择发货仓库并填写取件日期、运输类型、货物等公共条件，点击“开始自动询价”。收货地址来自所选组，收货地址类型和尾板设置应用于全部地址。地址、货物和公共条件在提交时保存快照，后续地址变化不影响历史。

## 部署

新增迁移 `0396_auto_quote_queue`（依赖已合并的 `0395`），创建地址、任务、明细及执行状态四张表。代码提交后，在部署环境执行：

```shell
python manage.py migrate
python manage.py collectstatic --noinput
```

Web 进程之外，启动一个常驻 worker，使用与 Web 相同的数据库和网关环境变量：

```shell
python manage.py run_auto_quote_worker --concurrency 3
```

使用部署平台的进程管理器保持运行并在退出时自动重启。不要把 worker 放入 Web 请求、浏览器定时器、Django `AppConfig.ready()` 或随请求启动的线程中。页面提示“后台执行服务尚未就绪”时，任务仍保存在数据库，检查 worker 的进程和日志即可。

已有网关配置 `MAERSK_GATEWAY_URL`、`MAERSK_GATEWAY_API_KEY`（或 `MAERSK_API_KEY`）继续复用。上线前先用小组验证网关限流；本地自动化测试不会调用真实网关。

默认并发3条，可设置1～10条。生产使用 PostgreSQL 行锁协调任务；建议只启动一个 worker。每进程提交请求至少间隔1秒、轮询请求至少间隔0.5秒，每个地址卡卡省轮询间隔3秒。一次地址执行最多4分钟，卡卡省轮询最多90秒、连续50秒无更新则返回已有报价。HTTP 429/5xx及连接超时最多尝试3次。

500条地址按平均每条1分钟估算，3并发约2小时47分，实际取决于报价平台响应及重试。页面每5秒更新任务状态，不需要保持页面打开。

## 运行与恢复

- 进度区分等待、运行、报价完整、部分报价、失败、无报价和已停止。
- 已返回的平台结果和卡卡省任务编号即时保存；worker 重启后，执行租约最多5分钟过期后接管未完成项，优先继续轮询原任务编号。
- “停止后续询价”取消未开始项，正在执行的地址完成后保留结果。
- “重试未完成项”仅对部分报价、失败、无报价及已停止地址创建新批次，关联原批次，保留旧报价。重试会重新查询平台。取件日期过期时需用新日期创建新任务。
- 若网络在网关接收提交后、返回任务编号前断开，调用方无法确定是否已提交；重试可能生成重复的外部询价。当前网关未提供已确认的提交幂等协议，不承诺外部请求严格只发生一次。
- 正常用户只查看和操作自己的任务；管理员可查看和操作全部任务。三组地址是共享地址资料。
- 自动历史独立于手动历史；可按执行状态筛选、分页查看、展开请求和返回明细，导出 CSV。每条记录保存实际开始与完成时间，CSV保留平台完整JSON结果。
- 距离只作地址资料展示，不用于报价计算。ABF沿用现有接入状态，不参与当前 Maersk / 卡卡省完成度判断。

## 价格分析

### 页面及收货地址历史（2026-09）

工作一览 → 三方询价下面有四个页面：手动询价、手动询价历史、自动询价、自动询价历史。自动询价入口为 `?step=auto_quote`，原 `?step=multi_carrier_quote&mode=auto` 链接仍可使用。创建页只负责地址组维护和提交；任务进度、查看结果、停止、重试、完整复制和导出集中在自动询价历史。

自动历史默认每个任务一行，显示点击提交的用户（重试任务记录本次点击重试的用户）。搜索地址、城市或邮编后，表格切换为跨任务的历史地址记录；日期按任务创建日期筛选。搜索查询历史快照，地址组后来修改不会改变旧结果。仍沿用访问权限：普通用户看自己的任务，staff 可看全部。

命中多个地址时先显示所有匹配记录，选择具体地址后才绘制单地址走势。图表按比较编号、取件提前天数、平台、币种分开，图表筛选不删减下方地址历史。每次询价取所选平台、币种中最低10个报价条目，按实际开始时间连线（未开始的使用任务创建时间）；同日多次与重试均保留。10条线代表价格名次，同一条线可能来自不同承运商或服务；悬停查看来源，图例可开关。缺价断线，不补0，少于10价只画实际返回数量。部分报价仍可展示并在点上提示；未知币种与假定USD按归档规则处理。现有承运商CV等多维分析入口保留，其每日末次采样规则与此逐次排名图不同。

历史每页30条，卡卡省默认最低10条，可展开完整列表；进入任务详情复制仍包含该任务全部地址及完整报价。图表最多处理所选编号最近1000次记录，超过会明确提示，可用日期缩小范围；表格仍可翻页查全部匹配历史。搜索匹配超过500个不同地址时需缩小关键词。地址视图点击“刷新任务”更新搜索结果，任务列表仍每5秒刷新。

本次页面拆分不新增模型或迁移。部署后运行 `python manage.py collectstatic --noinput` 并重启 Web 服务；已有自动询价 worker 继续按原方式运行。

新增验证：`python manage.py test warehouse.test_quote_destination_history --settings=warehouse.auto_quote_test_settings` 和 `node warehouse/tests_js/auto_quote_destination_ui.cjs`。

自动询价页面、自动历史以及每个任务的“价格分析”链接均可进入。新任务自动分配 `AQ000001` 形式的比较编号。相同物理发货地址、货物明细（描述、件数、尺寸、重量、板数）、申报价值、运输类型、车型、货物单位、托盘类型、地址类型和尾板条件复用编号；数值格式和货物行顺序不影响编号。条件变化会建立新编号。取件日期不放入编号，分析页面默认选择样本最多的取件提前天数（日历日），可手动调整。

迁移 `0397` 增加比较配置表 `AutoQuoteProfile`、独立报价明细表 `AutoQuotePrice` 及任务关联字段；`0398` 自动归档已有结果。每个接口报价保存一行，原始 JSON 继续保留。worker 完成每条询价时同时归档。升级时停止旧 worker，执行迁移和静态文件发布，重启 Web 和 worker。旧 worker 若继续运行可能留下未归档明细，页面会提示数量，可补跑：

```shell
python manage.py backfill_auto_quote_analysis
```

补归档可重复执行，不重复报价、不调用任何承运商接口、不覆盖原始结果。缺少必要参数的旧任务保留原样并报告，不能强行与其他条件比较。

可用分析角度：

1. **单线路价格曲线**：按平台、承运商和服务分别显示，支持图例开关、悬停价格、点击数据点回原任务。最多显示8条曲线，可筛选其他承运商查看。缺失报价处断线。
2. **最新涨跌**：显示最近采样日价格、前次有效价格、对应日期、金额变化及百分比；最新采样无报价就显示空白。
3. **区间统计**：首末有效报价涨跌、最低/最高/平均价、高低价振幅、相邻有效采样最大涨跌。
4. **波动最大/最小排名**：同线路 CV（总体标准差/均价）衡量相对波动；同平台承运商的不同服务分开。各服务使用共有线路集合，每条线路至少3个共同有效报价日，并以这些共同日期计算CV，再将各线路等权平均。不具备共同线路或共同日期时显示各自参考值，不指定最稳定/最波动。并列值显示并列。
5. **最低报价与提供方变化**：查看所选地址每天最低报价及全部并列提供方，识别低价变化是否伴随承运商改变。
6. **固定样本综合指数**：全部地址视图采用整个日期范围每天均有正数报价的固定线路/服务，每条首日归一100后等权平均，避免线路组成变化伪造涨跌。没有至少2个采样日或完整固定样本时不绘制。
7. **覆盖与质量**：报价有效日/采样日、覆盖率、样本不足、部分返回、未知标识、币种假定和未归档记录提示。
8. **筛选和导出**：比较编号、日期（最长366天）、地址组、地址、平台、承运商服务、取件提前天数、币种和部分报价筛选；CSV导出全部筛选结果，不限当前表格页。

按服务器时区，每天每个地址取最后发起且已结束的一次询价（包括失败）；同一天多次询价或重试不会增加权重。不同日期不把缺失补成零。同次同服务多个报价取最低参与分析，但独立明细及原始 JSON 全部保留。不同币种不换算混合；美国国内接口没有币种字段时标记为假定 USD。无代码时使用完整名称精确匹配，接口名称变动可能分为不同序列，不进行模糊合并。

排名是已采集样本的描述统计，样本覆盖不同仍需结合覆盖率判断，并非预测。仅有1～2个有效报价日时可以看价格及涨跌，不显示CV排名。0价保留，但0为基准的百分比不计算。未完整的平台报价默认排除；勾选包含后图表用空心点提示。

分析请求最多处理20000条已结束地址询价，超过时要求缩小日期或组；避免一次加载数十万原始JSON。价格明细查询只取统计必要字段，页面按50条价格序列分页。
